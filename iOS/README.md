# XBoardTest (BoardTestG for iPhone)

Generated by Godot's iOS export - do not edit by hand; export again instead. Open `XBoardTest.xcodeproj` in Xcode,
choose your iPhone as the run destination, and run (Team 4BB235M4GL, bundle id `com.iroiro.XBoardTest`, automatic signing).

Re-export from the project folder (the preset "iOS" is in `../export_presets.cfg`):

    /Applications/Godot.app/Contents/MacOS/Godot --headless --path .. --export-debug iOS iOS/XBoardTest.xcodeproj

After re-exporting, run `python3 patch_project.py` (adds `SUPPORTED_PLATFORMS = iphoneos`, see below).

## The Simulator does not work with this template

Choose a real iPhone as the run destination. Running on the Simulator on an Apple-silicon Mac fails for two reasons:

1. Godot 4.7.2's iOS template ships its simulator library (`ios-arm64_x86_64-simulator/libgodot.a`) as **x86_64 only**, in spite
   of the name. The Simulator is arm64, so the linker finds no `_main` ("Undefined symbol _main"). The project is marked
   device-only (`patch_project.py`), but Xcode still lists simulators; picking one installs a device binary and fails with
   "does not contain code for any platform ... runnable on this device".
2. I tried building an arm64 simulator library from the template's arm64 device library (retagging it as "iOS Simulator" and adding
   two missing Metal constants). It links and installs, but the Simulator's GPU lacks cube-array textures, which Godot's Mobile
   (Metal) renderer needs ("Your Apple GPU does not support ... image cube arrays"), and the Compatibility renderer sat at the
   Godot splash screen on the Simulator's software OpenGL. A newer export template, or one built from source with an arm64
   simulator slice, may fix the first problem; the GPU limit remains.

The game's folder `iOS/` has a `.gdignore`, so Godot does not scan or pack these generated files.
